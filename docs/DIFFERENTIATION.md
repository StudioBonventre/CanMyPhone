# Why CanMyPhone is not a tips app

Apple's Tips app and similar guides are useful catalogs. CanMyPhone is designed around a different interaction model.

## Catalog model

`Feature exists → publish a tip → user browses → maybe relevant`

## CanMyPhone model

`User has friction → understand it → ask if ambiguous → match device capability → guide setup → learn whether it helped`

## Product principles

1. **Problem-first, never feature-first.**
2. **Personal relevance beats volume.** Ten perfect suggestions are better than 500 generic tips.
3. **Native-first.** Do not recommend another app when the phone already solves the problem well.
4. **Conversation is a filter, not decoration.** Follow-up questions exist only to improve the recommendation.
5. **Device-aware.** Never recommend capabilities the user's model or OS cannot support.
6. **Outcome-aware.** The unit of success is not "tip viewed"; it is "problem solved".
7. **Learn over time with Need Radar.** Questions, opened solutions and explicit feedback should improve future suggestions while remaining opt-in and transparent.
8. **Source-backed.** Setup instructions must be verifiable.
9. **No hidden pay-to-rank.** Sponsorship never silently overrides a better free/native answer.
10. **Useful silence.** If there is no verified answer, say so and record the gap rather than hallucinating.
